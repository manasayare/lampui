1. Business context

LAMP runs a small manufacturer's whole business as one system. The business is described as a Business Tree (Functions, Processes, Activities, Tasks). Value Streams cut across the tree and execute as Runs. Agents do the work inside Tasks; people confirm what matters through chat, Telegram or the Cockpit. The first vertical is make-to-order (MTO) manufacturing in India.

Objectives

  • Give an Owner a deterministic yardstick for how the business runs (ADR-0005).
  • Replace the ERP: own System of Record, Ledgers and statutory Documents (ADR-0007).
  • Keep model cost at or under about 15% of the subscription (ADR-0009).
  • Ship the same Cell as SaaS and as licensed on-prem (ADR-0008).

Users

  • Owner: approves, sets Roles and Approval Rules, accepts Tree Changes.
  • Staff: work from Telegram, web chat and the Floor view.
  • Counterparties: customers and suppliers who receive Documents and messages.
  • The CA: receives GSTR-1, ITC-04, GSTR-3B and TDS files.
  • External Assistants: MCP clients acting for a signed-in person.

Value

  • Order to cash, procurement, production, quality, maintenance, HR, payroll, accounts and compliance in one flow.
  • GST, e-way bill, PF, ESI, PT and TDS rules as dated pack data kept current by Rule Watch (ADR-0015).
  • Every agent action explainable and in the append-only Audit Log.
  • English and Hindi throughout.

Metrics and thresholds

  • Critical Case pass rate: 100% (money, stock, statutory data, Counterparty messages).
  • Non-critical first-try eval pass rate: 90% or more.
  • Earned Autonomy: 8 passes and Wilson lower bound 0.97 for Auto.
  • RPO 5 minutes or less, RTO 4 hours or less per Cell (ADR-0018).
  • Plans: Starter ₹2,999, Growth ₹9,999, Pro ₹12,499 a month plus GST (ADR-0016).

2. Data flow

Everything enters through one door: the Application API. Every call is authorised as a person or the System Actor. The Run interpreter decides the route; agents only turn fuzzy input into structured data. State lands in the System of Record and the Ledgers, and leaves as Documents, messages and export files.

3. Processing pipeline: one step of a Run

Example: a customer order typed in chat becomes a sales order, a pick, a GST invoice PDF and Ledger postings. The same nine stages apply to every Value Stream.

Model tiers (ADR-0017)

TierUsed forNotes
T0 no modelRoutes, rules, postings, rendering, templated sends0.1 Credit per step

T2 midDocument photos and PDFs, quotation drafting, HSN suggestion, Deviation write-ups, tone judgeBOM and routing draft from a drawing
T3 frontierNew Value Streams, complex Tree Changes, one retry of a failed T2 contractBy exception only

When a Tenant's Credits run out, its Runs pause until refilled. All tiers route through OpenRouter zero-retention endpoints behind LiteLLM; LiteLLM publishes no host port.

4. System architecture

Three styles combined (ADR-0012): a modular monolith of bounded-context packages, hexagonal edges with one Application API and driven ports, and a microkernel (tree and runs) that executes content shipped as packs. A pnpm and Turborepo monorepo in strict TypeScript on Node 22.

6. Deployment

Model: Cells

A Cell is the unit of deployment: app, Postgres, file storage and LiteLLM gateway, packaged as containers. LAMP_CELL_KIND picks the kind.

dev

Docker Compose on a laptop. Mailpit for email, MinIO for files, local default passwords. pnpm dev.

saas

One pooled Cell on AWS Mumbai, backups to S3 with a copy in Hyderabad. Staging then production with blue/green. Not built yet: blocked on the AWS account (#133).

onprem

Single-Tenant bundle from infra/onprem with installer and hardening guide. Licence file signed by LAMP; 14 days of grace, then read-only. Cloud or Ollama models; POSIX or S3 backups.

air-gapped

On-prem without LICENCE_URL. Content updates with production pack signatures are in progress (#215).

Prerequisites

  • Docker with Compose v2.24 or later, Node 22 LTS, pnpm (never npm or yarn).
  • .env from .env.example with LITELLM_MASTER_KEY (required, starts with sk-) and OPENROUTER_API_KEY for real models.
  • LAMP_OWN_TENANT and LAMP_BUSINESS_PROFILES for signup, the waitlist and invoicing.
  • On-prem only: LAMP_CELL_ID, LICENCE_FILE, optional LICENCE_URL.

Build workflow: agents behind a merge gate (ADR-0022)

No human in the loop. Principle: no agent can change the rules it is judged by.

Gate checks, always read from main: install, typecheck, lint, boundaries, test, evals, rls, migrations, licenses, api-contract, coverage-and-mutation, packs-history, audit. Stop everything with the repository variable AGENTS_PAUSED=true.
